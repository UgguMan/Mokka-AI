# Mokka AI

**Three datasets train the classifier. Gemini explains matches and offers a separate tentative assessment when the model abstains.**

A local-first MERN application for preliminary plant leaf disease classification, with a model trained on PlantDoc plus mapped PlantVillage and PlantWild images, and an optional Gemini explanation/fallback layer.

## The intended flow

```text
ONE-TIME TRAINING
PlantDoc + mapped PlantVillage/PlantWild training images
    → frozen MobileNetV3-Small image features
    → train a class-balanced disease classification head
    → validation selects abstention rules
    → save trained model locally

EACH ANALYSIS
Uploaded leaf image
    → local trained model predicts PlantDoc class (or uncertain)
    → locked classification + image + optional observations go to Gemini
    → Gemini explains visible signs and the classification
    → server preserves the LOCAL label and saves the result without image bytes

EVALUATION
Untouched PlantDoc test images → same local model → measured metrics
```

**Gemini never overwrites the local disease label.** When the local classifier abstains, a separate structured `geminiAssessment` can suggest an outside-class disease, apparent health, uncertainty, or a non-leaf input. This is visibly tentative and does not change the local status or disease counts. Uncertainty does not prove a disease is absent from training. For supported local predictions, its explanation schema allows only the already predicted class; changed labels are rejected. Only narrative fields are copied into the result. If Gemini is not configured or fails, the local prediction is still displayed with an honest local summary and an explanation-unavailable notice.

This replaces the earlier VLM-only architecture. Existing saved VLM-only results remain viewable and are labeled as legacy Gemini classifications. New results store `predictionSource=plantdoc_local` and separate classifier/explanation metadata.

## Quick start

Requirements: Node.js 22.12+, npm, Python 3.11+, MongoDB Community, Git. The first dependency/model download requires internet. Local classification and evaluation subsequently run offline; Gemini explanations need internet and a free-tier API key.

```powershell
npm install
npm run setup
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ml/requirements.txt
npm run db:windows
npm run seed
npm run train:model
npm run dev
```

On macOS/Linux use `.venv/bin/python` to install requirements, and start MongoDB with your normal service or `mongod --dbpath <directory> --bind_ip 127.0.0.1`.

Open **http://localhost:5173**. Register/login to your Mokka AI account. The server is at http://127.0.0.1:5000. This account is separate from Google and your Gemini key.

The Windows DB helper uses an installed MongoDB, listens on loopback and stores data in `.local/mongodb`; if port 27017 is already in use it preserves the existing service. `npm run setup` generates a random JWT secret and never overwrites an existing `.env`.

### Gemini key

Create a free-tier key in [Google AI Studio](https://aistudio.google.com/apikey), keeping billing disabled. Add it privately to the root `.env`:

```env
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.5-flash-lite
```

Restart the app after changing `.env`. Never put this key in chat, screenshots, frontend code or `VITE_` variables. Without it, the PlantDoc model still classifies; Gemini explanations are simply unavailable. If your account/region requires billing, keep the local classification path instead of enabling paid services.

## Model training

The feature extractor is [MobileNetV3-Small](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html) with public ImageNet1K V1 weights. Its weights remain frozen. The disease-specific layer is a class-balanced multinomial logistic regression model trained on L2-normalized image features. **The disease head is trained on PlantDoc; Gemini is not trained or fine-tuned.** This is transfer learning with a frozen encoder, not training a CNN from scratch.

`ml/train.py` reads all supported training images, removes exact-byte duplicates, rejects undecodable/oversize-in-dimensions images, and creates a stratified 80/20 training/validation split with seed 42. The model fits only on the 80% partition. Validation selects a score threshold aiming for 80% selective accuracy and at least 20% coverage, if any threshold meets those criteria; otherwise a documented 0.5 score threshold is used. With `npm run train:combined`, supplementary official training images are appended after the original PlantDoc split, keeping its 467 validation images fixed. Imports exclude byte/pixel duplicates, preserve the original class taxonomy and cap each additional source/class at 300 images. A low feature-similarity threshold is also fitted on validation. Neither criterion guarantees reliability on unfamiliar inputs.

Outputs under ignored `ml/artifacts/`:

- `backbone.pt`: frozen image features, loaded with PyTorch `weights_only=True`.
- `head.npz`: learned classifier parameters and training reference features, loaded without pickle.
- `model.json`: labels, thresholds, versions and measured validation results.
- `split-manifest.json`: training/validation image hashes and skipped inputs.

Inference uses exactly the same image transform and classification math as evaluation. Express sends image bytes through a Python subprocess's stdin, not a disk file or command-line argument. There are at most two local predictions in flight and a 45-second timeout per subprocess.

Important limitations: this is a small-data baseline. Model scores are not calibrated probabilities. The similarity rule is an unfamiliar-input heuristic, **not a validated non-plant detector**. A novel plant or object can still be misclassified. The UI displays qualitative classifier certainty only and always advises expert review.

## Gemini's constrained role

The backend sends the locked label, photograph and escaped/delimited optional observations to the official `@google/genai` SDK. For matched classes Gemini can supply `visualSymptoms[]` and `reasoningSummary`. For abstentions the fallback schema is separate: `assessment`, `plantName`, `suspectedDisease`, `visualSymptoms[]`, `reasoningSummary`. The schema's classLabel enum contains exactly one permitted value, the local prediction. Zod rejects unknown fields and label changes. No Gemini-provided status, plant identity, disease identity or certainty overwrites the local result. Fallback suggestions are stored separately and clearly labeled unconfirmed.

The explanation is still generated text and may be inaccurate. Gemini is instructed to acknowledge conflicting/inconclusive visual evidence rather than invent signs or name a different diagnosis. Static conservative care recommendations replace free-form treatment instructions; no pesticide products or doses are requested.

SDK retries are disabled. One application retry is shared between malformed output and transient failures; network failures back off one second. Quota, configuration and safety errors are not automatically retried. A Gemini failure does not discard the local finding; the saved result clearly reports `explanationStatus=unavailable`. A quota notice includes a minimum retry hint, not a guaranteed quota reset time.

## Dataset provenance

Official classification repository: [pratikkayal/PlantDoc-Dataset](https://github.com/pratikkayal/PlantDoc-Dataset). Authors: Davinder Singh, Naman Jain, Pranjali Jain, Pratik Kayal, Sudhakar Kumawat, Nipun Batra. [Paper](https://arxiv.org/abs/1911.10317).

Verified snapshot `5467f6012d78d1c446145d5f582da6096f852ae8`, checked 2026-10-09: **28 train folders / 2,336 files; 27 test folders / 236 files**. `Tomato two spotted spider mites leaf` has no test folder. Valid/deduplicated training counts can be smaller and are recorded in the manifest.

License: **CC BY 4.0**. Original text is preserved in `dataset/metadata/PlantDoc-LICENSE.txt`; keep attribution when sharing derived data. The authors assembled images from the web; review third-party rights before redistributing images.

```powershell
git clone --depth 1 --no-checkout https://github.com/pratikkayal/PlantDoc-Dataset.git dataset/PlantDoc
python dataset/scripts/checkout_windows.py
npm run taxonomy
```

The extraction helper safely renames Windows-invalid or very long filenames, records changes in `filename-map.json`, and preserves image bytes and class folders. `buildTaxonomy.js` derives `{classLabel,plant,disease,isHealthy}` from actual folders. The taxonomy is shared by training, server validation, reference seed and evaluation. Retrain after changing it; inference checks its hash.

The library uses static general-reference notes maintained separately from predictions. The initial notes were assistant-authored and transparently marked as a draft needing manual agricultural expert review. They are not human-verified or claimed to be non-AI-authored. `npm run seed` upserts references without deleting users or analyses.

## Local evaluation

```powershell
npm run evaluate -- --perClass 3 --limit 30
npm run evaluate -- --perClass 3 --limit 60 --resume
# All available test examples:
npm run evaluate -- --perClass 1000 --resume
npm run metrics
```

Evaluation makes **no Gemini calls** and costs no API quota. It uses the same local feature extractor, trained head and abstention rules as the app. No ground-truth plant name or user text enters the classifier.

- Default sample: first 3 sorted test filenames per class. `--limit` applies to the selected sample, including cached entries. Increase it to extend a run.
- `--resume` reuses cached predictions. A model-version mismatch stops the run; preserve old results separately before evaluating newly trained weights.
- Duplicate bytes are evaluated once. Test images that exactly overlap training or validation are excluded and logged to reduce leakage. Near-duplicates may remain.
- `--delayMs` optionally delays between batches. `--retries` accepts 0/1 for CLI compatibility; deterministic local decoding failures are logged and not retried. There are no network requests to retry.
- Results: `evaluation/results/predictions.jsonl`, `failures.jsonl`, `metrics.json`, `confusion_matrix.csv`, `report.md`. A lock prevents concurrent writes. After an interrupted run, confirm the process stopped before removing a stale lock.
- Accuracy counts abstentions as incorrect. Coverage is non-abstained / successfully processed examples. Macro F1 averages classes with test support; zero-support classes are listed. The matrix has an uncertain/unsupported column for compatibility with legacy reports. The current local classifier only uses uncertain for abstention.
- Failed/skipped files are separately disclosed, excluded from metric denominators, and may bias the sample. Validation scores are distinct from held-out test scores. Never present small-sample performance as proven field accuracy.

See the generated evaluation report and `docs/verification.md` for the actual run status; no hard-coded performance numbers appear in the UI.

## Web application and data

React + Vite + Tailwind CSS + React Router + Axios; Node/Express ES modules + Mongoose + Zod + multer + sharp; Python/PyTorch/scikit-learn for the local disease model; Gemini for optional explanations.

Pages: landing, register/login, upload/context form, result with classification/explanation sources, history with delete, disease reference search/filters, dashboard with real owner-scoped MongoDB aggregates, methodology.

Collections:

- User: name, unique email, bcrypt password hash and timestamps.
- Analysis: user, local prediction, classifier version/certainty, explanation status/narrative, observations, Gemini metadata, image MIME/name/size, timestamps. Index on user + createdAt. No image bytes or image URLs.
- Disease: plant, disease, unique class label, general symptoms/information and provenance.

| Endpoint | Access / purpose |
|---|---|
| POST /api/auth/register, /api/auth/login | Public, rate-limited; returns one-hour token |
| GET /api/auth/me | Bearer JWT, current user |
| POST /api/analyze | Bearer JWT; in-memory image → local classifier → optional Gemini |
| GET /api/history?page=1 | Bearer JWT; owner's results, 12/page |
| GET or DELETE /api/history/:id | Bearer JWT; owner-only result read/delete |
| GET /api/diseases?search=&plant=&disease= | Public reference search/filter |
| GET /api/diseases/:id | Public single reference |
| GET /api/dashboard/stats | Bearer JWT; owner's real aggregates |
| GET /api/health | Configuration booleans, including localModelReady |

Security: Helmet; exact-origin CORS; bounded and sanitized text; JPEG/PNG/WebP magic-byte plus full decode checks; 4 MiB upload and 25M-pixel limits; one-hour HS256 JWT; bcrypt; owner-scoped queries; no raw secrets/provider errors/image data in logs. In-memory limits: 15 auth requests/15 minutes/IP and 8 analyses/minute/IP. Limits reset on restart and are best-effort across multiple processes.

Tokens are in sessionStorage. Logout clears the browser token but cannot revoke a stolen copy before expiry. XSS can read sessionStorage; a production system should consider httpOnly cookies with CSRF protection and revocation. Local image processing remains on the computer. If Gemini is configured, Google receives image/text and its free-tier data terms apply. Mokka AI never persists the upload.

## Deployment

The **full supported setup is localhost**. The dataset-trained Python process changes the hosting requirements: the previous Node-only Vercel API entry point has been removed. `vercel.json` now describes the frontend only; set VITE_API_URL to a separately hosted reachable API before building it. Do not deploy it expecting local Python or localhost URLs to run in Vercel. No public deployment has been performed.

Optional Atlas: select a Free cluster, create a least-privilege database user, restrict network access, set MONGODB_URI privately, and seed it. If obtaining suitable access at zero cost is not possible, stay local.

## Limitations and future work

Small/noisy dataset, unequal class sizes, missing test support, near-duplicates, possible ImageNet overlap, visual similarity, uncalibrated scores, imperfect unfamiliar-image rejection and generated explanation errors. This is educational decision support, not laboratory diagnosis. Future work: expert-reviewed notes, independent field data, stronger image/OOD validation, CNN fine-tuning comparisons, calibrated abstention, richer evaluation, and production session management.
